## 2. 事务与并发控制

### 2.1 ACID 特性实现

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                              ACID 特性实现                                       │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  A - Atomicity (原子性)                                                  │   │
│  │                                                                          │   │
│  │  实现机制: WAL (Write-Ahead Logging)                                     │   │
│  │                                                                          │   │
│  │  ┌─────────────────────────────────────────────────────────────────┐   │   │
│  │  │  BEGIN TRANSACTION;                                             │   │   │
│  │  │    UPDATE accounts SET balance = balance - 100 WHERE id = 1;    │   │   │
│  │  │    UPDATE accounts SET balance = balance + 100 WHERE id = 2;    │   │   │
│  │  │  COMMIT;                                                        │   │   │
│  │  └─────────────────────────────────────────────────────────────────┘   │   │
│  │                                                                          │   │
│  │  日志序列:                                                               │   │
│  │  ┌──────────┬──────────┬──────────┬──────────┐                        │   │
│  │  │ BEGIN TX │ UPDATE 1 │ UPDATE 2 │ COMMIT   │                        │   │
│  │  │  (1, -100)│ (2, +100)│          │          │                        │   │
│  │  └──────────┴──────────┴──────────┴──────────┘                        │   │
│  │                                                                          │   │
│  │  故障恢复:                                                               │   │
│  │  - 事务未提交 → Redo 日志恢复脏页 → 回滚未提交事务                       │   │
│  │  - 提交后故障 → Redo 日志重做已提交事务                                  │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  C - Consistency (一致性)                                                │   │
│  │                                                                          │   │
│  │  实现机制:                                                                │   │
│  │  1. 约束检查 (主键、唯一键、外键、检查约束)                              │   │
│  │  2. 触发器                                                               │   │
│  │  3. 锁机制确保并发操作不破坏完整性                                        │   │
│  │                                                                          │   │
│  │  示例:                                                                   │   │
│  │  ┌─────────────────────────────────────────────────────────────────┐   │   │
│  │  │  CONSTRAINT chk_balance CHECK (balance >= 0)                    │   │   │
│  │  │                                                                  │   │   │
│  │  │  -- 余额不能为负，事务提交前触发检查                               │   │   │
│  │  │  UPDATE accounts SET balance = -500 WHERE id = 1;  -- 失败!     │   │   │
│  │  └─────────────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  I - Isolation (隔离性)                                                  │   │
│  │                                                                          │   │
│  │  实现机制: MVCC + 锁                                                      │   │
│  │                                                                          │   │
│  │  隔离级别对比:                                                            │   │
│  │  ┌──────────────────────────────────────────────────────────────────┐  │   │
│  │  │  隔离级别        │  脏读   │  不可重复读 │  幻读   │  实现方式   │  │   │
│  │  │------------------│--------│------------│--------│------------│  │   │
│  │  │  READ UNCOMMITTED│   ✅    │     ✅      │   ✅    │ 无          │  │   │
│  │  │  READ COMMITTED  │   ❌    │     ✅      │   ✅    │ 快照读      │  │   │
│  │  │  REPEATABLE READ │   ❌    │     ❌      │   ✅*   │ 快照读+写锁 │  │   │
│  │  │  SERIALIZABLE    │   ❌    │     ❌      │   ❌    │ 全表锁/SI   │  │   │
│  │  └──────────────────────────────────────────────────────────────────┘  │   │
│  │                                                                          │   │
│  │  MVCC 工作原理:                                                          │   │
│  │  ┌─────────────────────────────────────────────────────────────────┐   │   │
│  │  │  每个事务有唯一的 TID，每个数据行有 xmin/xmax 版本字段            │   │   │
│  │  │                                                                  │   │   │
│  │  │  Row: { id: 1, value: "A", xmin: 100, xmax: NULL }              │   │   │
│  │  │       └── 当前版本，TID=100 的事务可见                           │   │   │
│  │  │                                                                  │   │   │
│  │  │  Row: { id: 1, value: "B", xmin: 101, xmax: NULL }              │   │   │
│  │  │       └── 更新后的版本，TID=101 的事务可见                       │   │   │
│  │  │                                                                  │   │   │
│  │  │  可见性判断: 当前事务 TID > xmin AND (xmax = NULL OR xmax > TID)│   │   │
│  │  └─────────────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  D - Durability (持久性)                                                  │   │
│  │                                                                          │   │
│  │  实现机制:                                                                │   │
│  │  1. WAL 日志必须先刷盘                                                    │   │
│  │  2. 检查点 (Checkpoint) 定期保存                                        │   │
│  │  3. 崩溃恢复                                                             │   │
│  │                                                                          │   │
│  │  刷盘策略:                                                                │   │
│  │  ┌─────────────────────────────────────────────────────────────────┐   │   │
│  │  │  commit = true                                                  │   │   │
│  │  │    │                                                            │   │   │
│  │  │    ▼                                                            │   │   │
│  │  │  WAL 日志写入内存缓冲区                                          │   │   │
│  │  │    │                                                            │   │   │
│  │  │    ▼                                                            │   │   │

│  │  │    │                                                            │   │   │
│  │  │    ▼                                                            │   │   │
│  │  │  释放用户连接/返回成功                                           │   │   │
│  │  └─────────────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 两阶段锁 (2PL) 与死锁检测

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                           两阶段锁协议 (2PL)                                     │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  阶段 1: 扩展阶段 (Growing Phase)                                               │
│  - 允许获取锁，不允许释放锁                                                     │
│                                                                                 │
│  阶段 2: 收缩阶段 (Shrinking Phase)                                             │
│  - 允许释放锁，不允许获取新锁                                                   │
│                                                                                 │
│  示例:                                                                           │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  T1:  LOCK(X) → READ(X) → WRITE(Y) → LOCK(Y) → UNLOCK(X) → COMMIT      │   │
│  │       └─ 扩展阶段 ─┘  │  └───────────── 收缩阶段 ─────────────┘         │   │
│  │                       │                                                │   │
│  │  问题: T1 释放 X 后，T2 可能修改 X，导致 T1 无法重复读                   │   │
│  │       这是"不可重复读"问题的来源                                          │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  严格两阶段锁 (Strict 2PL) - PostgreSQL/MySQL InnoDB 使用                │   │
│  │                                                                          │   │
│  │  规则: 所有锁持有到事务结束 (COMMIT/ROLLBACK)                            │   │
│  │                                                                          │   │
│  │  T1:  LOCK(X) → READ(X) → ... → COMMIT → UNLOCK(X)                     │   │
│  │                              ↑ 事务期间持有锁                            │   │
│  │                                                                          │   │
│  │  优点: 防止脏读、脏写、可重复读                                           │   │
│  │  缺点: 锁持有时间长，并发度降低                                           │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  死锁检测                                                                │   │
│  │                                                                          │   │
│  │  等待图 (Wait-For Graph):                                                │   │
│  │                                                                          │   │
│  │       ┌───────────────────────────────────────────────────────────┐     │   │
│  │       │                                                           │     │   │
│  │       │     T1 ──────▶│X│◀────────────── T2                       │     │   │
│  │       │               │锁│                                       │     │   │
│  │       │               ▲   │                                       │     │   │
│  │       │               │   │                                       │     │   │
│  │       │               │   │                                       │     │   │
│  │       │               │   │                                       │     │   │
│  │       │               │   │                                       │     │   │
│  │       │               │   │                                       │     │   │
│  │       │               └───┼───────────────────────────────────────┘     │   │
│  │       │                   │                                          │     │   │
│  │       │                   │                                          │     │   │
│  │       │           T1 等待 Y 锁                                        │     │   │
│  │       │           T2 持有 Y，等待 X 锁                                │     │   │
│  │       │           形成环 ──▶ 死锁!                                    │     │   │
│  │       │                                                           │     │   │
│  │       └───────────────────────────────────────────────────────────┘     │   │
│  │                                                                          │   │
│  │  检测算法: 定期检测等待图中是否存在环                                     │   │
│  │  解决策略: 选择代价最小的事务回滚 (undo log 最短)                         │   │
│  │                                                                          │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```

│  │  Clock-Sweep 置换算法                                                    │   │
│  │                                                                          │   │
│  │  ┌─────────────────────────────────────────────────────────────────┐   │   │
│  │  │  时钟指针 (clock hand) 循环扫描所有缓冲区:                        │   │   │
│  │  │                                                                  │   │   │
│  │  │  1. ref_cnt == 0 → 选择此页置换                                   │   │   │
│  │  │  2. ref_cnt > 0  → ref_cnt--, 移动到下一页                        │   │   │
│  │  │  3. 如果 dirty, 先刷盘                                            │   │   │
│  │  │                                                                  │   │   │
│  │  │  示例:                                                           │   │   │
│  │  │  ┌────┬────┬────┬────┬────┬────┐                               │   │   │
│  │  │  │ 1  │ 0  │ 2  │ 0  │ 1  │ 0  │  ← ref_cnt                    │   │   │
│  │  │  └────┴────┴────┴────┴────┴────┘                               │   │   │
│  │  │                ↑                                                │   │   │
│  │  │           clock hand                                            │   │   │
│  │  │                                                                  │   │   │
│  │  │  第一次: 遇到 1 → ref_cnt=0, 选中置换                            │   │   │
│  │  │  第二次: 遇到 2 → ref_cnt=1, 继续                                │   │   │
│  │  │  第三次: 遇到 1 → ref_cnt=0, 选中置换                            │   │   │
│  │  └─────────────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  脏页刷盘策略                                                            │   │
│  │                                                                          │   │
│  │  ┌─────────────────────────────────────────────────────────────────┐   │   │
│  │  │  策略 1: Checkpoint 定期刷盘                                      │   │   │
│  │  │  - 定时触发，将所有脏页写入磁盘                                    │   │   │
│  │  │  - 崩溃恢复时从检查点开始                                         │   │   │
│  │  │                                                                  │   │   │
│  │  │  策略 2: 后台写线程 (BGWriter)                                    │   │   │
│  │  │  - 持续将脏页异步写入磁盘                                         │   │   │
│  │  │  - 减少 checkpoint 时的 I/O 峰值                                  │   │   │
│  │  │                                                                  │   │   │
│  │  │  策略 3: 主动刷盘 (当缓存利用率低时)                               │   │   │
│  │  │  - 预留空闲缓冲区                                                 │   │   │
│  │  └─────────────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘

## 5. 面试高频知识点

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                           OLTP 面试高频问题                                     │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  分类 1: 事务与隔离级别                                                         │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  Q1: 解释 ACID 四个特性及其实现机制                                      │   │
│  │  A:                                                                        │   │
│  │  - Atomicity: WAL 日志，未提交事务的修改写入 Undo 日志                   │   │
│  │  - Consistency: 约束检查、触发器、级联规则                               │   │
│  │  - Isolation: MVCC + 锁机制，不同隔离级别不同实现                        │   │
│  │  - Durability: WAL + fsync + 检查点                                      │   │
│  │                                                                          │   │
│  │  Q2: 什么是脏读、不可重复读、幻读？                                      │   │
│  │  A:                                                                        │   │
│  │  - 脏读: 读取了其他事务未提交的数据                                      │   │
│  │  - 不可重复读: 同一事务两次读取同一行结果不同 (其他事务修改并提交)        │   │
│  │  - 幻读: 同一事务两次查询结果集不同 (其他事务插入/删除行)                │   │
│  │                                                                          │   │
│  │  Q3: MVCC 是如何实现的？                                                 │   │
│  │  A:                                                                        │   │
│  │  - 每行数据维护两个隐藏列: xmin (创建事务ID), xmax (删除事务ID)          │   │
│  │  - 每个事务维护一个 ReadView: active_txs[], min_txid, max_txid           │   │
│  │  - 可见性判断: txid < min_txid OR txid ∈ active_txs 则不可见             │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  分类 2: 并发控制                                                               │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  Q4: 什么是两阶段锁协议 (2PL)？                                          │   │
│  │  A:                                                                        │   │
│  │  - 扩展阶段: 只能获取锁，不能释放锁                                      │   │
│  │  - 收缩阶段: 只能释放锁，不能获取锁                                      │   │
│  │  - 问题: 级联回滚、死锁                                                  │   │
│  │                                                                          │   │
│  │  Q5: 如何检测和处理死锁？                                                │   │
│  │  A:                                                                        │   │
│  │  - 检测: 等待图 (Wait-For Graph) 中是否存在环                            │   │
│  │  - 处理: 选择代价最小的事务回滚 (undo log 长度)                          │   │
│  │  - 预防: 按固定顺序获取锁、超时机制                                       │   │
│  │                                                                          │   │
│  │  Q6: 行锁与表锁的区别？                                                  │   │
│  │  A:                                                                        │   │
│  │  - 行锁: 锁定行，并发度高，锁开销大                                       │   │
│  │  - 表锁: 锁定整表，并发度低，锁开销小                                     │   │
│  │  - 意向锁: 表锁和行锁 的兼容矩阵                                         │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  分类 3: 日志与恢复                                                             │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  Q7: WAL (Write-Ahead Logging) 的原理？                                  │   │
│  │  A:                                                                        │   │
│  │  - 先写日志到磁盘，再修改数据页                                          │   │
│  │  - 日志包含: 操作类型、旧值、新值、事务ID                                │   │
│  │  - 崩溃恢复: 扫描日志，按 Redo/Undo 恢复                                 │   │
│  │                                                                          │   │
│  │  Q8: Redo 和 Undo 的区别？                                               │   │
│  │  A:                                                                        │   │
│  │  - Redo: 重做已提交事务的修改 (前像日志)                                 │   │
│  │  - Undo: 回滚未提交事务的修改 (后像日志)                                 │   │
│  │                                                                          │   │
│  │  Q9: 什么是检查点 (Checkpoint)？                                         │   │
│  │  A:                                                                        │   │
│  │  - 将脏页刷新到磁盘，记录检查点位置                                      │   │
│  │  - 崩溃恢复时从检查点开始，减少恢复时间                                  │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  分类 4: 索引                                                                   │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  Q10: BTree 和 B+Tree 的区别？                                          │   │
│  │  A:                                                                        │   │
│  │  - BTree: 所有数据都在节点中                                             │   │
│  │  - B+Tree: 非叶子节点只存储键，叶子节点存储所有数据并链表连接             │   │
│  │  - B+Tree 优势: 查询稳定、叶子节点遍历友好、适合范围查询                  │   │
│  │                                                                          │   │
│  │  Q11: 为什么 B+Tree 比 BTree 更适合数据库索引？                          │   │
│  │  A:                                                                        │   │
│  │  - 树高更小: 非叶子节点只存键，可容纳更多扇出                             │   │
│  │  - 范围查询友好: 叶子节点链表连接                                         │   │
│  │  - 查询稳定: 必须查到叶子节点                                             │   │
│  │                                                                          │   │
│  │  Q12: 什么是索引回表？如何优化？                                         │   │
│  │  A:                                                                        │   │
│  │  - 回表: 先在索引中查到主键，再回主索引查完整行                          │   │
│  │  - 优化: 覆盖索引 (索引包含所有查询列)、索引下推                         │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
│  分类 5: Buffer Pool                                                           │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  Q13: Buffer Pool 的作用？                                               │   │
│  │  A:                                                                        │   │
│  │  - 减少磁盘 I/O                                                         │   │
│  │  - 提供并发访问控制                                                      │   │
│  │  - 支持脏页刷盘                                                         │   │
│  │                                                                          │   │
│  │  Q14: LRU 和 Clock-Sweep 的区别？                                       │   │
│  │  A:                                                                        │   │
│  │  - LRU: 维护访问时间戳，代价高                                           │   │
│  │  - Clock-Sweep: 使用引用计数近似 LRU，开销小                             │   │
│  │                                                                          │   │
│  │  Q15: 脏页何时刷盘？                                                     │   │
│  │  A:                                                                        │   │
│  │  - Checkpoint 触发                                                      │   │
│  │  - Buffer Pool 空间不足                                                 │   │
│  │  - 后台 BGWriter 线程                                                   │   │
│  │  - 脏页比例超过阈值                                                     │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```
