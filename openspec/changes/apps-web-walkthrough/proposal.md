## 背景

做好了界面重做，用户提了一句：**「我要的是真实应用拉起之后第一个界面长啥样，
点了各个地方会有什么效果」**。

之前给的 `preview.html` 是**开发工具** —— 左边是 47 个页面的目录树，
右边 iframe 里是真应用。它对开发有用，但不对「想知道这个应用怎么用」的人有用：
- 目录树是给开发者看的页数清单，不是使用路径
- 只有 47 个平铺的页面，看不出「从哪进、点了会怎样」
- 没有点击反馈 —— 不知道点待办的圆圈会发生什么

## What Changes

### 新增 `apps/web/web/walkthrough.html`

**真实操作导览** —— 左边是 19 步真实使用路径，右边 iframe 里是**真实运行的应用**，
每一步会**真的点下去**（不是描述，是 `el.click()`）。

| 分组 | 步骤 |
|---|---|
| 一、拉起来第一眼 | 应用首页 → 点「程序员工作台」 |
| 二、工作台：今天在做什么 | 今日 → 点待办圆圈 → 点优先级药丸 → 点心情 → 点「添加待办」 |
| 三、工作台：其它四页 | 技术 → 生活 → 工具 → 我的 |
| 四、知识中心 | 知识中心 → 去刷题 → 知识图谱 |
| 五、AI 简报 | AI 简报 → 点一篇简报 |
| 六、足迹与游戏 | 足迹 → 游戏 → 玩 2048 |

机制：

- **同源驱动** —— 导览页由应用服务端提供（`/walkthrough.html`），
  iframe 与它同源，所以能操作真应用的 DOM
- **`file://` 打开时自动跳转**到服务端版本，否则跨源拿不到 `contentDocument`
- **真点击** —— `el.click()`，真应用自己处理；提示条里的「已点击」是实际发生的
- **高亮框** —— 在真应用里叠一个绝对定位的框圈住目标元素，
  滚动到它、跟着它动（列表重绘时不跑偏）
- **`peek` 与真点分开** —— 只是「看这里」的步骤不高亮点击，
  会产生副作用的步骤（勾待办、记心情）才真点
- **步骤条可点、可前后翻** —— 也能完全自己动手，右边 iframe 是活的

### 顺带修一个真 bug（导览跑出来时发现的）

`shared/platform.js` 里两处用了 `element.children.indexOf(...)` / `.splice(...)`：

- `showToast` 的清理 —— **提示条永远消不掉**
- `closeMask` —— **遮罩删不掉**，对话框关掉后整个应用被一层看不见的盖子挡住

原因：`children` 在浏览器里是 `HTMLCollection`，**没有 `indexOf` 也没有 `splice`**。
测试里之所以是绿的，是因为 `tests/dom-stub.js` 的 `children` 是**数组**。

两处改成 `node.parentNode.removeChild(node)`。

### 新增 `apps/web/tests/platform-dom.test.js`

一个 `children` 只读（没有 `indexOf`/`splice`）的 DOM 桩 —— 把浏览器的真实约束
搬进测试。三条用例：提示条会消失、对话框取消后遮罩移除、确认后遮罩移除。
