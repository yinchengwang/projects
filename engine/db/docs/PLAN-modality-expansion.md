| # | 模态 | 对标 | 状态 | 落在哪 |
|---|---|---|---|---|
| 1 | 关系 / OLTP | PG | ✅ | v0.1–v0.7（heap + MVCC） |
| 2 | 大对象 blob | S3 / GridFS | ✅ | v0.8（对象→帧→随机访问） |
| 3 | 图 | Neo4j | ✅ 排期 | v0.11（定长记录 + 邻接链） |
| 4 | 向量 / ANN | hnswlib | ✅ 排期 | v1.0（列式布局 + HNSW） |
| 5 | **全文检索** | **Lucene** | ❌ 未排期 | **本计划 → v1.3** |
| 6 | **地理空间** | **PostGIS** | ❌ 未排期 | **本计划 → v1.4** |
| 7 | **时序** | **InfluxDB / Gorilla** | ❌ 未排期 | **本计划 → v1.5** |
| 8 | **文档 / JSON** | **MongoDB** | ❌ 未排期 | **本计划 → v1.6** |

**排序理由**（索引类 → 存储类 → 类型系统类，依赖从少到多）：

1. **全文（v1.3）**：倒排索引是 IndexAM 之外的**新索引范式**，且 segment
   不变 + 合并是 Lucene/Lance/LSM 共同的灵魂 —— 学习价值最高、依赖最少。
2. **空间（v1.4）**：R-tree 是 IndexAM 的第三个实现（`knn` 口子又多一个用户），
   与 v1.0 的经验直接衔接。
3. **时序（v1.5）**：动存储层布局（分区 + 压缩），比索引类的改造面大。
4. **文档（v1.6）**：动类型系统 + 变长 schema-less，最贴近 SQL 层 ——
   放最后，因为它对前面所有抽象（外部值、下推、catalog）的检验最全面。

**每版开工前的纪律**：写独立 `PLAN-v1.x.md`（对齐 v0.8–v1.2 的格式：
判决表 + 验收 + 风险 + 分步计划），把本总览的"验收草案"细化成可执行项。

## 1 · v1.3 全文检索（Lucene segment 对标）

### 学的是什么

**不变文件 + 后台合并**。Lucene 的核心洞察：
索引文件写完就**不可变**；删除只打标记；后台把多个小 segment 合并成大 segment
（合并时才物理丢弃被删除的文档）。blob 的对象不可变、v1.5 时序的分区压缩、
Lance 的 fragment —— 全是同一个思想。全文模态是把这个思想学透的最佳载体
（它的合并策略最有讲究）。

### 关键判决（预判，立项时细化）

| 问题 | 预判 | 理由 |
|---|---|---|
| 分词器 | **英文：小写化 + 空格/标点切分**。中文分词明确不做 | 分词器是独立工程（词典/统计模型），对理解倒排索引零增量 |
| 索引结构 | 倒排表：`term → (doc_id, tf)` 有序数组；term 字典用有序数组 + 二分（FST 是优化，不做） | 学的是 posting list 机制，不是字典压缩 |
| 打分 | **BM25**（k1=1.2, b=0.75，论文默认值） | 事实标准；TF-IDF 作为对照实现 |
| 删除 | 打标记（posting 里跳过）+ 合并时物理丢弃 | Lucene 同款 —— **这正是学习点，别绕过它** |
| 合并策略 | **Tiered**：segment 数超阈值 → 挑最小的几个合并 | Lucene 默认策略；log-structured 合并作为对照 |
| 与 MVCC 的关系 | 语句级可见（segment 带创建 LSN，查询按快照过滤 segment）—— 立项时细化 | 倒排没有"行版本"，可见性只能挂在 segment 粒度 |
| SPI 对接 | 虚拟表 `ft_docs`（文档表）+ `match(col, 'term')` 谓词下推到全文 AM；倒排本身是 AM 内部结构，不暴露为 IndexAM | match 语义（相关性排序）不是标量比较，硬塞进 IndexAM 会扭曲接口 |

### 验收草案

| # | 项 |
|---|---|
| A1 | 检索结果与**线性扫描的 BM25 排序**全等（小语料，千文档级） |
| A2 | 删除后文档**立即**不出现（标记生效），合并后仍不出现（物理丢弃生效） |
| A3 | 合并前后检索结果全等；**IO 可证**：合并后单 term 查询页读数下降（segment 数变少） |
| A4 | **合并的增量代价**：10 万文档分批插入，合并总 IO 与 document 数呈 `O(N × log_f N)` 量级（放大系数可测可解释） |
| A5 | 崩溃恢复：segment 文件 + 删除标记全在 WAL 保护下，恢复后结果一致 |
| A6 | 执行器零改动；旧验收全绿 |

## 2 · v1.4 地理空间（PostGIS R-tree 对标）

### 学的是什么

**多维数据的索引**：B+tree 的键是一维全序，空间数据没有全序 ——
R-tree 用**最小包围矩形（MBR）嵌套**把"二维邻近"变成"树内聚集"。
窗口查询 = 子树剪枝；KNN = mindist 优先队列。

### 关键判决（预判，立项时细化）

| 问题 | 预判 | 理由 |
|---|---|---|
| 树结构 | **R-tree**（Guttman 1984），不用 Quadtree/KD-tree | PostGIS 同款；磁盘页友好（高扇出）；Quadtree 留作对照实验 |
| 几何类型 | **2D 点和矩形**。多边形不做 | 点/矩形已覆盖 R-tree 的全部机制（分裂、剪枝、mindist）；多边形只增加求交代码量 |
| 插入分裂 | Guttman 原始启发式：子树选择 = 面积最小扩张；分裂 = 种子拣选 + 面积最小切割 | 论文原版；R*-tree 变体是优化，不做 |
| **键编码之争** | **真 R-tree**（树节点存 MBR），**不做 Z-order 一维编码塞 B+tree** | Z-order 能复用 B+tree 但**学习增量是零**（B+tree 已经学过了）；本版要学的是"多维树自己的分裂/剪枝逻辑"。Z-order 作为对照实验（比较窗口查询 IO）倒是值得做 —— 它正是真实系统（PG 的 GiST 之外的 SP-GiST 路线）的另一半故事 |
| KNN | `IndexAM.knn` 的第三个实现：mindist 优先队列遍历 | 复用 v0.9 留的口子、v1.0 验证过的调用路径 |
| SPI 对接 | `geometry` 列（存 `x,y` 或 `minx,miny,maxx,maxy` 的二进制）；`WHERE ST_Within(p, box)` 类谓词下推给空间 AM | 判决：不做完整 ST_ 函数族，下推接口收窄为"窗口相交 + KNN"两个原语 |

### 验收草案

| # | 项 |
|---|---|
| A1 | 窗口查询结果与暴力扫描全等（含边界情况：恰好在边界上的点） |
| A2 | KNN 结果与暴力排序全等（含距离并列时的稳定顺序） |
| A3 | **IO 可证**：10 万点，1% 选择率的窗口查询页读数 < 全扫的 1/10 |
| A4 | 删除 + MBR 收缩（或标记死 MBR）：删除后窗口查询不返回死点 |
| A5 | 崩溃恢复：树结构重建（复用 `reindex` 路径）后查询结果一致 |
| A6 | 对照实验：Z-order + B+tree 与 R-tree 的窗口查询 IO 对比，数字可解释（各自什么时候赢） |
| A7 | 执行器零改动；旧验收全绿 |

## 3 · v1.5 时序（InfluxDB / Gorilla 对标）

### 学的是什么

**为写入优化的存储布局 + 列级压缩**。时序数据的特点：
按时间有序追加、几乎不更新、旧数据变冷 —— 于是：
时间分区（冷热分离）、封闭分区压缩（delta-of-delta 时间戳、RLE、Gorilla 浮点）、
保留策略整分区丢弃。**"分区封闭后不可变"又是不变文件思想** ——
第三次出现（Lucene segment → 向量列式 → 时序分区），至此这条线索可以收拢总结。

### 关键判决（预判，立项时细化）

| 问题 | 预判 | 理由 |
|---|---|---|
| 分区 | 按时间范围（默认 1 天，可配）；分区 = 独立的物理页区间；分区元数据进 catalog（新系统表 `sys_partition`） | 分区元数据是查询裁剪的依据，必须进 catalog（对比 blob 自己管目录——时序的分区要被**通用查询**按时间裁剪，得让执行器看得见） |
| 活跃分区 | 追加写、不压缩（ slotted page 或定长行）；**封窗后压缩成列式页**（时间列 delta-of-delta，浮点列 Gorilla，整数列 RLE/delta） | Gorilla 论文（Facebook 2015）的原方案；"活跃不压缩、封窗才压缩"是写入吞吐和存储成本的平衡点 |
| 查询跨分区 | **执行器不改**：时序 AM 的 scan 按 WHERE 的时间谓词裁剪分区（谓词下推的又一个应用）——AM 返回的仍是"行源" | §5.3 的同构性原则的强测试：分区裁剪完全藏在 AM 内部 |
| TTL / 保留策略 | `RETENTION POLICY`：整分区过期 → 页区间整体回收进 freelist（blob 同款"整块回收"） | 逐行删旧数据是时序场景的大忌；分区粒度丢弃才是时序的写法 |
| 更新/删除 | **不做**（时序数据不可变是建模前提）；`DELETE FROM ... WHERE time < T` 走"丢弃边界分区"的特例 | 立项时把特例的边界情况写清（边界分区内有未过期数据怎么办——只做整分区） |
| SPI 对接 | `ts_readings` 虚拟表；时间谓词下推 → 分区裁剪；压缩列的解码走 `decode` 回调 | 下推契约不变：裁剪错只会慢不会错（多读分区 = 超集） |

### 验收草案

| # | 项 |
|---|---|
| A1 | 压缩正确性：压缩→解压→与原始行逐行全等（delta-of-delta / RLE / Gorilla 各自单测 + 全链路） |
| A2 | **压缩比可测**：随机数据与真实感数据（缓变 + 抖动）各测一组，压缩比数字可解释（Gorilla 对缓变数据显著优于随机） |
| A3 | 跨分区查询：时间谓词裁剪命中分区集合正确（多读不漏 —— 超集断言） |
| A4 | TTL：过期分区整体回收后，页计数下降、查询不含旧数据、freelist 复用正常 |
| A5 | 崩溃恢复：活跃分区（WAL）+ 封闭分区（压缩页）混合恢复后全量校验一致 |
| A6 | IO 可证：裁剪后查询页读数 ≈ 命中分区大小，与总数据量无关 |
| A7 | 执行器零改动；旧验收全绿 |

## 4 · v1.6 文档 / JSON（MongoDB 对标）

### 学的是什么

**schema-less 的代价与对策**。前七个模态的行结构都是"建表时定死"；
文档模态的行是**自描述的**——每行有自己的字段集。
要学的机制：二进制文档格式（解析一次反复用）、路径寻址、
**路径索引**（给没进 schema 的字段建索引）、变长文档的页外存放。

### 关键判决（预判，立项时细化）

| 问题 | 预判 | 理由 |
|---|---|---|
| 文档格式 | **JSONB 二进制树**（解析一次、按路径 O(子树) 访问；PG JSONB / MongoDB BSON 同款思路），不存原始文本 | 文本存法每次查询重新 parse，无法建路径索引；JSONB 的偏移量结构正是"文档怎么变成可寻址数据"的答案 |
| 存储 | 小文档进 slotted page（一行一文档）；**大文档走外部值**（v0.9 机制的第 3 个用户：blob 帧 → 大 JSON 页链） | 外部值契约不用改 —— `ext_fn` 从 blob 的"按帧读"换成"按页链读"，句柄 + 惰性物化的设计原样复用。**这是 v0.9 设计 foresight 的最终检验** |
| 类型系统 | `JSON` 列类型走 §10.2 的"模态特有类型"先例（VECTOR 同款），不进通用类型系统 | JSON 值的比较/编码规则自成一体，塞进四标量类型系统会污染所有层 |
| 路径索引 | `CREATE INDEX ... ON t (path '$.a.b')`：提取路径值作为 B+tree 键（提取在**写入时**做，索引存的是标量快照） | 复用现有 B+tree + index_key —— 学习点是"从自描述文档提取可索引标量"的物化策略，不是新树 |
| 查询接口 | `SELECT doc->'$.a.b' FROM t WHERE json_match(doc, '$.a.b = 5')`；`json_match` 谓词：有路径索引 → 下推；无 → 执行器解析 JSONB 过滤 | 下推契约原样适用：索引快照可能过期（文档更新了但索引项未删）→ AM 返回候选集，执行器**重新解析求值** —— 超集语义又一次兜底 |
| 更新语义 | 整文档替换（MongoDB 的 update 也是文档级操作符，本版只做替换）；可见性跟随 heap 的 MVCC（文档行就存成 heap 行，JSONB 是列值） | **判决：文档模态不建独立存储，作为 heap 上的列类型 + JSONB 编解码 + 路径索引** —— schema-less 的难点在值表示与索引，不在存储（heap 已经把变长行做对了）。这是与 blob/graph/vector 不同的接入深度：文档是**寄生模态** |
| SPI 对接 | 无新 AM！`heap_am` 的 `decode` 支持 JSON 列 → `DbValue` 加 external JSON 变体；路径索引走既有 IndexAM | 验证 SPI 的另一种扩展方式：**不改接口、只加深实现** |

### 验收草案

| # | 项 |
|---|---|
| A1 | JSONB 编解码：parse→binary→按路径取值，与原始 JSON 语义全等（对照 SQLite JSON1 函数逐条全等） |
| A2 | 大文档外置：> 页大小的文档走外部值，**IO 可证**（只取路径字段时不读全文） |
| A3 | 路径索引：`json_match` 走索引时页读数 < 全扫；索引快照过期时结果仍正确（执行器重求值兜底） |
| A4 | MVCC：文档更新走 heap 版本链，RR 快照下文档不撕裂 |
| A5 | 崩溃恢复：文档 + 路径索引（reindex 重建）恢复后一致 |
| A6 | 旧验收全绿；依赖方向正确 |

## 5 · 四版之后的收口：这条主线学完了什么

v1.6 完成时，八个模态齐了。把三条贯穿性的线索收拢（写进 DESIGN.md 的复盘章节）：

| 线索 | 出现处 |
|---|---|
| **不变文件 + 后台合并** | blob 对象不可变 → Lucene segment 合并 → 向量列式页 → 时序分区压缩 —— 四次同构，一次总结 |
| **句柄 + 惰性物化（外部值）** | blob 帧（v0.9 首创）→ 向量（v1.0）→ 大 JSON（v1.6）—— 三种"大值"一个机制 |
| **下推只能给超集** | blob_id 下推 → 图边链下推 → 全文 match → 空间窗口 → 时序分区裁剪 → JSON 路径索引 —— 六次应用，零次违反 |

之后的扩展（JOIN、图算法、量化、跨模态联合查询）全部进**需求驱动池** ——
八模态内核的学习目标达成后，再开新篇就是另一个项目了。
