## 一、方案

### 1.0 这一版要证明什么

时序数据的三特点（按时间有序追加 / 几乎不更新 / 旧数据变冷）决定了它的存储形态：

> **为写入优化的布局 + 封窗压缩 + 整分区丢弃。**
> 活跃分区裸写（快），封窗后压缩成列式（小），过期整块回收（省）。
> —— "分区封闭后不可变"是不变文件思想的第三次出现（blob → Lucene segment → 这里）。

两个判据：

1. **执行器零改动**（本版最核心的验收）：分区、压缩、裁剪**全部**藏在 AM 内部 ——
   执行器看到的仍然只是"行源"。这是 §5.3 同构性原则的最强测试。
2. **压缩比可解释**：缓变数据显著优于随机数据（Gorilla 的设计前提），
   数字能对照论文的量级（Facebook 报告 ~10×+ 的典型压缩，随机数据远达不到）。

### 1.1 范围

**做：**

1. 时间分区：按时间范围（默认 1 天，可配），分区自管目录 + `ts_partitions` 虚拟表。
2. 活跃分区：slotted page 追加写（复用 heap 的页管理）。
3. 封窗压缩：`PT_TS_COL` 列式压缩页 —— 时间列 delta-of-delta、整数列 delta+RLE、浮点列 Gorilla。
4. 时间谓词下推 → **分区裁剪**（无时间谓词 = 裁剪退化为全分区，超集安全）。
5. TTL / 保留策略：整分区过期 → 页区间回收进 freelist。
6. WAL（活跃分区整页镜像；封窗重写前后镜像）。

**不做（明确划掉）：**

| 项 | 为什么 |
|---|---|
| 乱序写缓冲（OOO buffer） | 写路径按时间戳路由到正确分区即可；乱序让压缩率下降是**如实记录的代价**，不是要修的 bug |
| 降采样 / 连续查询 | 查询层特性，与存储内核无关 |
| 多指标宽表（一行多列指标） | 单指标模型（time, tag, value）已覆盖全部存储机制；宽表是 schema 糖 |
| 块级倒排（时间范围 → 列块索引） | 页级统计（min/max）进页头即可，独立的块索引是优化 |
| 更新 / 删除单行 | 时序不可变是建模前提；唯一的删除路径是 TTL 的整分区 |

### 1.2 关键判决

#### 判决 1（修正总览预判）：分区元数据自管，不进 catalog

总览（PLAN-modality-expansion §3）预判"分区元数据进 catalog（sys_partition 新系统表）"。
**细化时被推翻**，理由记录如下：

| 路径 | 分析 |
|---|---|
| 进 catalog（sys_partition） | 前提是"要被通用查询裁剪就得让执行器看得见" —— **这个前提不成立**：裁剪发生在 AM 的 `push` 里（拿到时间谓词后查自己的分区表），执行器从头到尾不需要知道分区存在 |
| **自管目录 + `ts_partitions` 虚拟表** | ① `blob_id` 下推的同款先例（blob 自管对象目录，下推时自己查）；② 硬规则 6 的一致性更强：**catalog 不知道任何模态**（blob/graph/vector/ft 都没进 catalog，时序凭什么进）；③ 用户可见性由虚拟表解决（`SELECT * FROM ts_partitions`），不需要系统表 |

> **这正好是"总览 → 独立 PLAN 细化"环节的价值证明**：预判阶段看起来必须共享的结构，
> 对照既有先例逐条过堂后，发现自管更一致。执行记录里保留这次修正。

#### 判决 2：封窗（seal）的时机与原子性

```
活跃分区（裸写）── 满/超时 ──→ 封窗压缩（不可逆）──→ 封闭分区（只读）
   slotted page                    列式压缩页                PT_TS_COL
```

- **触发**：分区行数 ≥ 阈值（config.h）或时间窗滑过（封窗 = 最后一次写之后）。
- **原子性**：压缩 = 新写一组 `PT_TS_COL` 页 → 段头记 `sealed_lsn` → 旧 slotted 页回收。
  崩溃窗口（新页写完、旧页未回收）由恢复逻辑收敛：重放后发现新旧并存 → 用新页、旧页进 freelist。
  （**判定规则：`sealed_lsn` 落盘即封窗成功** —— 对齐 v0.6 的"meta 页是根指针"手法。）

#### 判决 3：压缩三件套（逐列选型）

| 列 | 编码 | 出处 |
|---|---|---|
| 时间戳 | **delta-of-delta**（变长 zigzag：常间隔 → 0x0 一个 bit） | Gorilla 论文（Facebook 2015） |
| 整数（tag id 等） | **delta + RLE**（重复值游程） | 通用时序实践 |
| 浮点（value） | **Gorilla XOR**（与前值异或 → 前导零/尾零计数 + 有效位） | Gorilla 论文 |

**封窗分区是列式的**（对齐 v1.0 向量列式页的先例）：
每列一段连续页，行号 → 列内偏移有页级换算。**活跃分区是行式的**（slotted page）——
两种布局在同一个模态里共存，"封窗"就是格式转换的时机。这也是学习点：
**列式不是 everywhere 的，是"冷数据"的**（Lance/ClickHouse 的现实约束同构）。

#### 判决 4：TTL 的页回收

`db_ts_retention(conn, seconds)` → 过期分区整块回收：

```
分区页区间 → freelist（页号空间共享，回收的页可被任何结构用）
分区目录项 → 标记 dropped（虚拟表仍可见历史，标 state）
```

**回收进 freelist 的合法性**（对照 v0.8"blob 页不进表 freelist"）：
那条规定说的是"**表的** freelist"（每表独立、语义是"哪页能放下 N 字节的行"）；
时序回收走的是**全局页分配器的空闲回收**，与 blob 新分配页同一条路（`pager_alloc` 的对侧）。

#### 三个设计决定

**① 位流只有一份，三个编码共用。**

三件套都要在**位**的粒度上读写（"常间隔 → 1 bit"、"XOR 为 0 → 1 bit"）。
三个编码各写一套位流 ⇒ 三份几乎一样的代码 ⇒ **迟早有一份的位序不一样**
⇒ 读出来全是垃圾，而且**不报错**（长度校验可能刚好通过 —— 坑 M6-1）。
所以位流抽到 `tsbits.{h,c}`，谁都不许自己重写。

**② 格式与错误码的约定写死在头文件里，三个编码一模一样。**

- 格式（v1）逐条写在各自的头文件里（谁来实现都不用再猜）。
- **成功返回数量（≥ 0），失败返回**负的**错误码** ⇒ 调用方一律 `rc < 0` 判错。
  ⚠️ 这与仓里其它模块"rc = E_xxx（正数）"的写法**相反**，
  是本组三个编码**特有**的约定（坑 **M6-19**）。
  （实现过程中 `gorilla.c` 一度写成了正数，两个同事报上来的失败行号互相矛盾 ——
  最后查出来是**跑的是旧二进制**，见下面"顺带修掉的构建坑"。）

**③ 截断 / 乱码 / 容量不足一律**硬失败**。**

解码端遇到读坏、条数对不上、缓冲区不够，一律返回 `E_CORRUPT` / `E_NOSPACE`，
**绝不"读不出来填 0"** —— 那会把一段坏数据静默变成一段看着正常的数据。
每件套都有一条"砍掉每一个更短的长度都必须报错"的测试。

#### A1 实测（1000 点，供 A3 bench 对照）

| 编码 | 数据形态 | 字节/点 | bit/点 |
|---|---|---|---|
| **时间列（delta-of-delta）** | 恒定间隔（每秒一个点） | **0.133** | 1.06 |
| | 抖动 ±1s | 0.958 | 7.66 |
| | 随机时间戳（最坏） | 8.683 | 69.46 |
| **整数列（delta + RLE）** | 全同值 | **0.003** | 0.02 |
| | 每次 +1 递增 | 2.000 | 16.0 |
| | 全随机 i64（最坏） | 10.485 | 83.9 |
| **浮点列（Gorilla）** | 恒定值 | **0.133** | 1.06 |
| | 小步长（每次 +0.25） | 1.362 | 10.9 |
| | 缓变 ±1% 抖动 | 6.825 | 54.6 |
| | 随机（最坏） | 8.252 | 66.0 |

**三组结论（每组一句）**：

1. **恒定 / 等间隔 ⇒ 1 bit/点**，这是三种编码各自的理论下界
   （时间列 dod 恒为 0；浮点列 XOR 恒为 0；整数列整段游程）。
2. **缓变数据收益远小于预期**：Gorilla 对 ±1% 抖动只省 15%（6.83 vs 8 字节），
   因为 XOR 之后**指数位不变、尾数高位仍在变**，有效位还剩 ~40 位。
   Gorilla 真正的主场是"小步长"（1.36 B/点）。
   ⚠️ 这与 Facebook 论文报告的 ~10× 有差距 —— 论文的典型场景是
   **整数计数器**，不是浮点监控值；这一点如实记下来，A3 bench 要按实测口径讲。
3. **随机数据下可能比原始 8 字节/点还大**（Gorilla 8.25、RLE 10.49）——
   这是位级 varint 的性质（每组占满一字节），**不是 bug**。
   ⇒ **A3 bench 要按"压缩比可能 > 1"的口径设计**，不能默认编码一定变小。

#### 顺带修掉的一个构建坑（比三件套本身更重要）

实现中途出现了"改了源码、make 报 BUILD OK、但跑的是旧二进制"的现象，
两个同事报上来的失败行号互相矛盾。

查出来是 **Windows 上 make 的 `$(shell find ...)` 静默返回空**：
make 的 `$(shell ...)` 走 cmd.exe，而 cmd.exe 里**单引号不是引用符**，
`'*.c'` 被原样传下去 ⇒ find 命中的是 **Windows 自带的 find.exe**
（文本搜索工具，不是 findutils）⇒ SRCS 为空 ⇒ **make all 什么都不编，而且不报错**。

修法（坑 **M6-20**）：SRCS 改用 make 内建的 `$(wildcard ...)`（不经过 shell），
SHELL 在 Windows 上给 Git 自带的 sh 的**绝对路径**。
验证：改一个源文件 → 对象文件时间戳跟着变；`make -n all` 里 ts 源从 0 个变成 5 个。

> **教训**：**"编译成功"不等于"编译的是你刚改的那份"**。
> 构建系统自己骗你的时候，测试结论会全部变成假象。
> 这也是计划 §1.4 风险 R6「反向验证编译不过 → 跑旧二进制」的**同一个坑**，
> 只是这次它自己咬到了我们头上。

#### 如实记录（不注水）

- **A1 只覆盖编解码本身**：不碰页、不碰事务、不碰分区。
  "写进去再读出来还是一样"这件事要到步骤 3（封窗）才成立。
- **浮点比的是位模式，不是 `==`**：NaN payload、±0.0 都能逐位还原
  （`==` 比不出来 —— NaN != NaN，±0.0 == 0.0）。
- **随机数据下压缩比 > 1**（见上），A3 bench 别按"一定变小"设计判据。
- **格式没有条数字段**："声明的条数比实际多"只能在"位不够"时被抓到。
  ⇒ 步骤 2/3 的**块头**要自己记 count（这三条会写进列存页的段头）。
- **rle 的变异测试发现首轮有一条没被抓住**（畸形流只有两个 0，
  解码端"跳过空段读到末尾"也能撞出 CORRUPT）——
  把用例改成"count=0 后面补一段合法数据"之后才抓住。
  ⇒ **畸形输入的用例要设计成"只有这一条路能导致失败"**。
- **还没做的**：分区目录、活跃分区写、封窗、读路径、裁剪、TTL、SPI、公开 API、WAL
  —— 分别是步骤 2~6。

#### 三个设计决定

**① 目录自管，不进 catalog（计划判决 1）。**

meta 页（`PT_TS_META = 0x17`）+ 目录页链（`PT_TS_DIR = 0x18`）。
**目录项定长 32 字节**，一页最多 126 条；放不下**自动扩页**，绝不静默丢分区。
目录项的字段本来就是契约固定的（`TsPartInfo` 六个字段）⇒ 变长的好处拿不到，
定长反而能按序号直接算出偏移（不用维护槽位表）。

**开库两条路**：`ts_dir_open()` 扫页空间找 meta 页（与 geo 同口径，坑 M6-22）；
`ts_dir_open_hint()` 由调用方直接给页号 ⇒ **零扫描** ——
这是给将来 db 层接线的出路（"页号 → 模态"的登记处正好在 catalog 手里，
而 catalog 不知道任何模态，所以这条路只能由 db 层来铺）。

**② spill = 页写满了续开一张页，分区数不变。**

⚠️ **这是与计划措辞的偏差**：计划写的是"分区写满了就新开一个分区"。
改掉的理由三条：

1. 契约里 `TsPartInfo.page_count` 只有在"一个分区可以有多页"时才有意义（否则恒为 1）；
2. **"一个时间窗 ↔ 一个分区"是 R3 路由不变式的基础** ——
   一页满就新开分区 ⇒ 同一时间窗出现多个分区 ⇒ 目录查询不知道回哪一个 ⇒ **静默漏数据**；
3. 封窗压缩是步骤 3 的事，步骤 2 不封窗，分区只能靠多页长大。

实测 400 行 ⇒ 1 个分区 3 页（169 + 169 + 62）。

**③ 目录里的 `n_rows` / `page_count` 是水位线。**

只在分区 spill（页数变了）时落盘；对外 API 返回**运行时的真值**；
开库时以**页链实际数出来的**为准并回写目录。
理由：每写一行就改一次目录 = 一行一次 4KB 页写，写放大离谱。
代价：崩在两次 spill 之间，目录里的行数偏小 ——
但开库会数回来，**不会漏数据**，只是多读一遍页链。

#### 验收（8 组，全过）

1. **时间路由**：1 天 / 1 秒 / 7 天三种窗口；边界左闭右开
   （`t = part_start` 归本窗、`t = part_end` 归下一窗）；
   **负时间戳**（`-1 → -1 天`、`-1 天 → -1 天`、`-1 天−1 → -2 天`）；
   再对 13 个时间戳 × 5 种窗口做**不变量自检**
   （`part_start ≤ t < part_start+span`，且路由幂等 `route(route(t)) == route(t)`）。
2. **跨分区写入**：3 个时间窗 6 行 ⇒ 分区数 3、每分区 2 行、窗口起止正确；
   每个时间戳 `find_part` 都能找回自己的分区。
3. **读取**：读回来的与写进去的**逐条相等**，浮点比**位模式**
   （含 `-0.0`、1/3、1e-300、1e300 这些"难看"的值）。
4. **R3 负例**：不在任何分区里的时间戳 ⇒ **E_NOTFOUND**，
   **不返回"最近的那个分区"糊弄**。
5. **关库重开**：数据还在，目录也重建出来。
6. **spill**：400 行 ⇒ 1 个分区 3 页、行数 400、扫描 400 条全对；**再关库重开复验一遍**。
7. **参数**：`span_sec=0` ⇒ E_INVAL；空库 `ts_store_open` ⇒ E_NOTFOUND
   （与 geo / graph 同口径）；改窗口只影响之后的写入。
8. **诊断**：分区数 / 总行数 / 数据页数 / 累计逻辑页读。

#### 如实记录（不注水）

- ⚠️ **本模态还没有 WAL**（坑 M6-31）：契约里没有 WAL 钩子参数，
  所以这一层不写日志。崩在写入中间 ⇒ 丢行，或目录与数据页不一致（开库报 E_CORRUPT）。
  补 WAL 要改契约头文件，是**步骤 6** 的事。
- ⚠️ **开库成本随数据量线性增长**（坑 M6-32）：
  扫页空间找 meta 页（M6-22）+ 走一遍分区页链数行（M6-30 的回填代价）。
  与 geo 的坑 M5-9 同量级 —— 同一个病根（模态不许碰 catalog）。
- ⚠️ **改分区窗口后新老窗口可能重叠**（坑 M6-34）：
  当前规则是"**起点靠后的分区优先**"（与 `ts_dir_find` 的二分口径一致），
  不是"最窄优先"。极端情况下分区归属可能与直觉不符 —— 步骤 4 再定严格规则。
- **目录的崩溃一致性只做到"不静默丢"，还没做到"不丢"**（坑 M6-23）：
  断电可能停在"尾目录页写了一半" ⇒ 该页校验和不过 ⇒ 开库报 **E_CORRUPT**
  （而不是读出半截目录当正常）。追加新分区只写链尾的新页、老页不动
  ⇒ 断电最多丢掉"最后没写完的那一个分区"。
- **meta 页里的条目数是水位线**（坑 M6-24）：写顺序是"先目录页、后 meta 页"，
  所以断电只可能让链上条数**多于** meta 记的 ⇒ 以链为准；
  链上条数**少于** meta 记的 ⇒ 链被截断 ⇒ E_CORRUPT。
- **还没做的**：封窗压缩、读路径认封闭分区、裁剪、TTL、SPI、公开 API、WAL
  —— 分别是步骤 3~6。

#### 三个设计决定与偏差

**① 封窗原子性 = 目录项是唯一权威。**

两步：① 先写列式页、**不改目录**；② 再翻目录项（`ACTIVE → SEALED`）。
崩在中间 ⇒ 目录还是 ACTIVE ⇒ 读到**完整旧分区**，列式页成孤儿
（浪费空间、**不丢数据**）。
反过来先翻目录就会读到**半截列式数据** —— 半截数据往往"看起来正常"，比直接报错坏得多。
重开库时只看目录项，不会出现"新旧并存"。

**② ⚠️ 偏差：没有 `sealed_lsn`。**

计划判决 2 定的原子性规则是"`sealed_lsn` 落盘即封窗成功"。
但本模态**没有 WAL ⇒ 没有 LSN** ⇒ 改用单调递增的**封窗序号** `seal_seq`
（记在列式头部页），它只标识次序、**不参与恢复判断**（恢复只看目录项状态）。

**③ ⚠️ 未做：「时间窗滑过」这个触发条件检测不到。**

计划写的是"行数 ≥ 阈值**或**时间窗滑过（封窗 = 最后一次写之后）"。
问题：**没人写的时候，没有谁来触发检查** ——
要么给写路径加一个"每次写都看当前时间"的钩子，要么加一个后台线程。
本轮只做"行数 ≥ 10000"这一条，**如实记账**（坑 M6-45），留给步骤 6 / v1.6。

**④ ⚠️ 旧页只标记、不回收** ⇒ 文件只涨不缩（与 geo 的 reindex 同一个代价）。
连带后果：目录里的 `page_count` 记的是**列式页数**，与文件实际占用不再相等（坑 M6-42）。

### 步骤 4 · 裁剪 + TTL（2026-11-04）

**结论：完成（A4 的前置与 A6 的主体落地）。**

#### 落地的东西

| 文件 | 行数 | 内容 |
|---|---|---|
| `src/modalities/ts/ts_prune.{h,c}` | 196 + 291 | 分区裁剪 |
| `src/modalities/ts/ts_ttl.{h,c}` | 174 + 323 | TTL 整分区过期 |
| `src/storage/pager_free.c` + `pager.{h,internal.h,c}` | 140 + 改动 | **pager_alloc 的对侧**：全局页空闲栈 |
| `test/unit/test_ts_prune.c` / `test_ts_ttl.c` | 432 / 401 | 6 组 + 7 组验收 |

#### 三个设计决定

**① 裁剪只能少读，不能少给（计划坑 M6-5）。**

核心是一条**纯函数** `ts_prune_window_hits(start, end, t_lo, t_hi)`
（相交判据 `start <= t_hi && end > t_lo`，两端含 ⇒ **超集**），
**写入侧与读出侧调同一个函数** —— 两处各写一遍，
早晚有一处不一样，而"不一样"的方向如果是"少给"，就是**静默漏数据**。

没有谓词 / OR / 函数包裹 / 范围反了 ⇒ **返回全部分区**，绝不猜。

**② TTL 的顺序不可反。**

先把目录项改成 DROPPED（并清空首页/页数）→ `pager_flush_all` 落盘
→ **才**把页还给全局空闲栈。
反过来崩在中间 ⇒ 目录说分区还在、页已经被别人用了 ⇒ **静默读到别人的数据**。
同时保证**幂等**：已经 DROPPED 的分区跳过。

**③ TTL 接口接受"当前时间"参数。**

`ts_ttl_expire(pg, dir, now_ms, ttl_sec, stats)` —— `now_ms` 由调用方传。
理由：TTL 判定必须是"拿现在去比"的纯函数式，
测试才能造出确定的边界（`end == now − TTL` 不过期）；
也让上游能传数据库自己的时钟而不是墙上时间。

#### 补上了一个前置缺口：pager_alloc 的"对侧"

计划判决 4 说 TTL 回收的页"进入全局页分配器的空闲" ——
但 pager 此前**只会往文件尾追加**，没有对侧的可用实现。
本轮补上 `pager_free()` / `pager_free_count()`：
空闲栈挂在 pager 上（属**全局页号空间**，任何结构都能复用），
与 `storage/freelist.h` 的"表的 freelist"（每表独立、不能跨表用）**语义不同**，
后者没有被改动。

#### 如实记录（不注水）

- ⚠️ **全局空闲栈只在内存里、不落盘**（坑 M6-52）：
  关库后回收的页变成"文件里的空洞" —— 既不复用也不误用（安全方向），
  但也**没有真正回收**。要根治需要 WAL 或 catalog 登记。
- ⚠️ **封窗分区被换掉的旧裸写页，TTL 不收** —— 属封窗流程自己的事。
- ⚠️ `ts_prune_scan` 与 `ts_store_scan` 各自做了一份"按分区状态分派读页"，
  逻辑重复（步骤 3 的读路径统一后可以退化掉）。
- ⚠️ TTL 后 `ts_store` 的 `row_count` 仍按内存计数
  （存活分区正确）；目录里 DROPPED 项的 `n_rows` 在重开库时会被水位线回填清零
  （**历史行数丢失**，属 tsstore 既有行为，不在本步修）。
- ⚠️ **无 WAL ⇒ TTL 的"落盘"只到"写进文件"**（`pager_flush_all`），不含 fsync。

#### 三个设计决定与偏差

**① 契约装不下的字段 ⇒ 首成员技巧（坑 M6-53）。**

契约里的 `TsAmCtx` 只有 {st, writable}，而 AM 还要装"表种类"与"时间范围"。
解法：新增 `TsAmExt{TsAmCtx base; ...}`，
`_Static_assert(offsetof(base) == 0)` 钉死布局，`&ext.base == &ext` 零拷贝转回。
⇒ **契约头一个字都没改**。

**② 下推走 `can_push` / `push`，不只靠上下文（坑 M6-54）。**

契约把范围挂在**上下文**上 ⇒ 那是实例级共享状态（所有连接共享），只能当"默认范围"。
真正的查询路径用 `push()`（范围在**扫描状态**里，不共享）。
`can_push` 只认"时间列 vs 整数常量"的 `>=` / `>` / `<=` / `<`，
其余一律 `E_NOTSUP` **退回全扫**；
`push` 只翻成**半开区间**给**超集**（`>=v` ⇒ `[v, +∞)`），
完整的 WHERE 仍由执行器算 —— **裁剪只少读、不少给**。

⚠️ **偏差**：`ts_am_set_time_range()` 按契约实现了，但**当前没有调用方**
（执行器那条路走 `push`）—— 如实记下。

**③ ⚠️ 接口裁决：TTL 必须用"存储自己那份"目录（坑 M6-57）。**

TTL 要操作存储的目录，而对外契约里**没有**取目录的入口。
早期实现直接 include 了模态的私有头 `ts_store_int.h` **越过了契约**。
已在 `tsstore.h` 补上只读出口
`const struct TsDir *ts_store_dir(const TsStore *st)`，并把私有头 include 去掉。

理由不是"洁癖"：另开一份目录副本去跑 TTL ⇒
TTL 改了副本、存储内存里的目录还是老的 ⇒
查询会去读**已被回收的页** ⇒ **读到别人的数据而且不报错**。
