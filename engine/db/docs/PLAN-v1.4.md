## 一、方案

### 1.0 这一版要证明什么

B+tree 的键是**一维全序**；空间数据没有全序 —— 这版的主题是：

> **多维数据怎么进树**：R-tree 用最小包围矩形（MBR）嵌套把"二维邻近"
> 变成"树内聚集"。窗口查询 = 子树剪枝；KNN = mindist 优先队列。

三个判据：

1. **正确性**：窗口 / KNN 结果与暴力扫描全等（含全部边角）。
2. **剪枝真的发生**：1% 选择率的窗口查询页读数 < 全扫的 1/10。
3. **两条路线的对照有结论**：真 R-tree vs Z-order+B+tree（把二维映射成一维塞进已有树），
   各自什么分布下谁赢 —— **数字可解释**。这是真实系统里 GiST vs SP-GiSt 路线之争的微缩版。

### 1.1 范围

**做：**

1. `geometry` 二进制列：`POINT(x,y)` 与 `RECT(minx,miny,maxx,maxy)`。
2. R-tree（Guttman 1984 原始版）：插入 / ChooseSubtree / 二次分裂 / 窗口查询 / mindist KNN。
3. Z-order 对照实现（点 → Morton 码 → B+tree，窗口 = 区间分解）。
4. 虚拟表 `geo_points` + 专用 API `db_geo_window / db_geo_knn`。
5. 删除 = 标记死条目（不 rebalance，对齐 B+tree 的先例）+ `reindex` 重建。
6. WAL（整页镜像）+ 崩溃恢复。

**不做（明确划掉）：**

| 项 | 为什么 |
|---|---|
| 多边形 / 线串 | 点/矩形已覆盖 R-tree 全部机制（分裂/剪枝/mindist）；多边形只加求交代码量 |
| R*-tree / STR 批量加载 | 重插入与批量打包是插入质量的优化；先学原始启发式 |
| 空间 JOIN / 距离 JOIN | 需要 JOIN（§10.1 维持不做） |
| 坐标系 / 投影 / 测地距离 | 假定平面直角坐标（PostGIS 的 geography 模式明确不做） |
| 空间谓词进 SQL（ST_ 函数族） | v1.3 §1.2 的同一边界：几何语义不进标量谓词系统（专用 API） |

### 1.2 关键判决

#### 判决 1：真 R-tree，不做 Z-order 一维编码塞 B+tree

| 候选 | 判决 |
|---|---|
| (a) 点 → Morton 码 → 塞进现有 B+tree | **否决（作为主路径）** —— 复用 B+tree 学习增量是零；窗口查询要拆成多个 Z 区间（BigMin 算法），逻辑绕 |
| (b) **真 R-tree**（节点存 MBR 数组） | **采纳（主路径）** —— 要学的就是多维树自己的分裂与剪枝 |
| (a') Z-order 作为**对照实现** | **采纳（bench 路径）** —— 与 R-tree 比 IO，结论可解释 |

**学习增量论**（写进 DESIGN 复盘）：复用已有结构的工作量小，
但本项目的目标是"把机制亲手实现一遍" —— Z-order 塞 B+tree 学的是 Morton 编码，
真 R-tree 学的是多维树。对照实验把两者的真实代价差摆出来，这比单独做任何一个都完整。

#### 判决 2：R-tree 的键不走 `index_key`

`index_key`（v0.9 从 query/ 下沉）解决的是"列值 → 一维可比字节串"。
R-tree 的"比较"是**相交 / 包含 / mindist**，不是全序比较：

```c
/* R-tree 的键就是 MBR 结构体，直接存进树页条目： */
typedef struct { float minx, miny, maxx, maxy; } Mbr;

/* 树页条目（PT_RTREE 页）：
   内部节点：[child_page, Mbr] 数组（Mbr 概括整棵子树）
   叶子节点：[row_id,    Mbr] 数组（点 → 退化 Mbr） */
```

**IndexAM 的接口够用吗**：`knn(am, query, k, out)` 的 query 是 `void*`（传 Mbr/点），
范围扫描的语义换成"窗口"—— `IndexAM` 是模态级契约，R-tree 作为它的第三个实现
（btree → hnsw → rtree），接口零改动。

#### 判决 3：KNN 是精确的（与 v1.0 形成对照）

HNSW 的 KNN 是**近似**（ef 换召回）；R-tree 的 mindist 优先队列是**精确**算法：

```
优先队列（按 mindist(节点MBR, 查询点) 最小堆）：
  弹出 → 若是叶子条目：入结果集（真实距离）
        → 若是内部节点：把子条目按 mindist 压栈
  结果集满 k 个且堆顶 mindist ≥ 第 k 近的真实距离 → 提前终止
```

> ⚠️ **修正（步骤 3 实做时发现，2026-11-03）**：终止条件里的 `≥` 必须是 **`>`**。
>
> 理由与判决 4 的 tie-break 直接相关：当堆顶 mindist **等于**第 k 近的真实距离时，
> 未展开的子树里可能藏着**等距但 row_id 更小**的点 ——
> 按 tie-break（row_id 升序）它本该排在第 k 名**之前**，
> 取 `≥` 会提前停掉、漏掉它，于是 KNN 与暴力基准**不一致**。
>
> 即：`≥` 只在"不需要 tie-break"（距离各不相同）时才对；
> 一旦引入 row_id tie-break，终止条件就必须严格大于。
> 已在代码里记为坑 M4-44，验收里也专门构造了"并列临界 k"的用例组，
> 并用**变异测试**证明这条判据抓得住（把 `>` 改成 `>=` → 24 处断言变红）。

**两版对照是设计教育点**：近似的代价是召回、收益是跳过大部分树；
精确的代价是必须展开所有"可能更近"的子树、收益是结果无懈可击。
验收里两边的对照方法不同（recall vs 全等），这个差异本身要写进文档。

#### 判决 4：并列距离的稳定顺序

浮点距离并列时（网格点、对称分布），KNN 的第 k 名可能不唯一：
**tie-break 定死为 row_id 升序**。暴力对照实现用同一规则 —— 否则"全等"验收会被浮点噪声随机击穿。

#### 三个设计决定

**① 边界语义钉成「闭区间」，并写进可执行的断言。**

空间的正确性事故几乎都是**静默漏点**：少算一个边界，答案少几个点，
而且**不报错**。所以这一步把"共边算不算相交""落在边上的点算不算在窗内"
逐条写成断言（`test_geo_mbr.c` 的 `test_overlap` / `test_contains`），
而不是留在注释里靠后人自觉。

- 点落在矩形边界上 → **在窗内**；
- 两个矩形共边（相接） → **相交**（剪枝不能剪掉它）。

**② 几何算术必须「单一来源」。**

R-tree 与暴力基准**共用** `modalities/geo/mbr.c` 的每一个函数。
若两边各写一份"距离"，浮点末位差异会让"结果全等"这条验收
被噪声随机击穿 —— 验收就变成了掷骰子。
所以 `geo_dist2`（两点距离平方）被单独抽出来，
让"树里叶子条目的真实距离"与"暴力基准的距离"走**同一条表达式**。

**③ 距离一律用平方距离；并列一律按 row_id 升序。**

- 少一次 `sqrt`，且 `sqrt` 单调 → 排序结果完全一致；
- 浮点距离并列时（网格点、对称分布 —— 空间数据的**常态**）
  "第 k 名"不唯一，必须有确定规则。
  **tie-break 定死为 row_id 升序**（计划 §1.2 判决 4），
  树与暴力都遵守同一条。

#### 如实记录（不注水）

- 本步骤**没有**碰页、没有碰锁、没有碰 WAL —— 它是纯函数层。
  所以这一步"跑得快、测得全"**不能**说明 R-tree 会好使；
  真正的考验在步骤 2（分裂拣选）与步骤 3（KNN 提前终止）。
- 暴力 KNN 的"装不下"判据在实现过程中**改过一次**：
  原判据是"`k > max_out` 就报错"，改成了
  **"结果个数 = min(k, 点数)，装不下才报错"**。
  理由：`k` 是**请求**、`n` 是**事实** ——
  "要 10 个而库里只有 2 个点"是事实，不是容量错误。
  若按旧判据，`k=10, n=2` 会报错，那是把"数据少"误判成"缓冲区小"。
- 暴力实现用 `qsort`（`GeoHit{d2, row_id}` 结构体数组）。
  代价是 O(n log n) 全排序，不是 O(n log k) 的部分选择 ——
  对"验收尺子"够用，但它**不能**被当成 KNN 的性能基线。

#### 页格式（定长条目，不用 slotted page）

```
偏移  长度  字段
  20    1   flags      bit0 = 1 → 叶子
  21    1   reserved
  22    2   n_entries
  24    4   level      叶子 = 0
  28    4   n_points   **只写在根页**（非根为 0）
  32   ...  entries[]  每条 20 字节
```

条目 20 字节 = `u32 id`（叶子是 row_id、内部是 child_page）+ 16 字节 MBR。
两种条目一样长 ⇒ 节点页只有**一套**布局、**一条**代码路径。
一页装 203 条（`(4096-32)/20`），分裂后每组至少 102 条。

**为什么 `n_points` 只写根页**：内部节点的子树点数 = 孩子子树点数之和，
而条目里没有地方放"孩子的点数"（要算就得把每个孩子页都读一遍 ——
分裂时那一下就是两百多次页读）。只记在根上，重开树读一次根页就知道总点数。

#### 三个设计决定

**① 剪枝判据与命中判据必须同源。**

剪枝用 `mbr_overlap`（包围盒与窗口不相交就整棵子树不下去看），
命中用 `mbr_contains_point`（**闭区间**，边界上的点算命中）。
两处都走 `mbr.h` 的同一套函数 —— 否则边界点会在两边得出不同结论，
"结果全等"这条验收就废了。

**② 叶子条目的 MBR 是"点的退化矩形"（min == max）。**

这样叶子与内部条目共用同一个 `Mbr` 结构与同一套距离函数，
KNN 的"叶子真实距离"和"子树 mindist"才能走同一套算术（步骤 3 兑现了这一点）。

**③ 内部条目的 MBR 必须是"精确包围盒"，不是虚胖的盒子。**

测试里**绕开树里记的 MBR**，从叶子往上独立重算子树包围盒，再逐位比对。
虚胖的 MBR 不会漏点，但会让剪枝**静默失效** —— 查询变慢而且不报错。

- **树高没有硬上限检查的兜底测试以外的保护**：`RT_MAX_DEPTH = 64` 是防御值，
  正常分裂路径不会走到它。

### 步骤 3 · mindist 精确 KNN（2026-11-03）

**结论：完成（A3 通过）。**

#### 落地的东西

| 文件 | 行数 | 内容 |
|---|---|---|
| `src/modalities/geo/rtree_knn.h` | 64 | API：`rtree_knn` / `rtree_knn_npoints` |
| `src/modalities/geo/rtree_knn.c` | ~370 | 最小堆（mindist2）、结果集（d2, row_id）、提前终止 |
| `test/unit/test_geo_knn.c` | ~430 | A3：全等（含顺序）/ 并列 / 边界 / 页读 |

#### 为什么单独一个文件

`rtree.c` 已经 785 行（上限 800），再加 KNN 会超限；而且 `rtree.c` 的内部状态是私有的。
所以 KNN 是**自包含模块**：自己按 `rtree.h` 里公开的页布局读节点页，
调用方只需持有 `Pager` 与根页号。

#### 算法

```
根页读一次：
  根是叶子 → 逐条算真实距离 geo_dist2，进结果集
  根是内部 → 每个孩子按 mindist2 压最小堆
主循环：
  弹堆顶
  若 结果集已满 k 且 堆顶 mindist2 **>** 第 k 近的真实距离 → 终止
  读该页：叶子 → 逐条算真实距离；内部 → 孩子压堆
```

结果集按 `(d2 升序, row_id 升序)` 维持有序；满了之后只有"比第 k 名更好"的才挤掉它。

#### 三个设计决定

**① 终止条件必须是严格 `>`（坑 M4-44）。**

堆里每个元素的 `mindist2` 是"这棵子树里所有点到查询点的**距离下界**"。
设第 k 近的真实距离是 `d_k`：

- `mindist2 > d_k` ⇒ 这棵子树里**不可能**有距离 ≤ d_k 的点 ⇒ 剪掉安全；
- `mindist2 == d_k` ⇒ 这棵子树里**可能有距离恰好等于 d_k 的点**，
  而按 tie-break（row_id 升序）它可能排在当前第 k 名**之前** ——
  剪掉就会漏点。

即：`>=` 只在"距离不会并列"时才对。空间数据里并列是常态（网格、圆环、对称分布），
所以判据必须是 `>`。计划 §1.2 判决 3 原文写的是 `>=` —— 那是计划的缺口，
已就地打了 ⚠️ 修正标记。

**② 距离算术与暴力基准同源。**

叶子条目的真实距离一律走 `geo_dist2()`，剪枝用的下界一律走 `mbr_mindist2()` ——
与 `geo_brute_knn()` 用的是**同一套算术**。浮点末位差异会让"全等"验收变成掷骰子。

**③ 结果个数 = min(k, 点数)，装不下才 `E_NOSPACE`。**

`k` 是**请求**、点数是**事实** —— "要 10 个而库里只有 2 个点"不是容量错误。
（这条判据在步骤 1 的暴力基准上已经改过一次，KNN 沿用同一口径。）

#### A3 验收（`test_geo_knn.c`）

| 项 | 对照方式 |
|---|---|
| 随机点全等 | 1000 个确定性随机点 × 40 个查询 × k∈{1,2,3,5,10,37}，**顺序也逐位相同** |
| 网格点全等 | 40×40 网格 × 60 个查询（格点 + 格心）× k∈{1,2,3,4,5,10,50} |
| 并列 tie-break | 12 个**精确等距**的圆环点（x²+y²=25）+ 600 个远处点，k 从 1 扫到 20 逐个对照 |
| 边界与退化 | k > 点数 → 返回点数；max_out 装不下 → E_NOSPACE；k==0 / 空树 → 0 条 |
| 页读 | 4000 点：k=1 → **2 页**，k=1000 → 18 页，全扫窗口 → 15625 页 |

实测输出：

```
[页读] k=1: 2，k=1000: 18，全扫窗口: 15625
```

k=1 只碰了 **2 页**（根 + 一片叶子），全扫要 15625 页 —— 剪枝是真的在发生。

#### 变异测试：这条判据抓得住吗

断言"全等"到底有没有牙齿，光看绿灯不算数。做法是**故意把实现改坏**：

| 变异 | 结果 |
|---|---|
| 终止条件 `>` 改成 `>=` | **24 处断言变红**（网格查询第 1 名/第 9 名与暴力不一致） |

改回 `>` 后恢复全绿。这证明 A3 不是"恰好通过"，而是真的在盯着这条判据。

#### 如实记录（不注水）

- **页读口径是"逻辑页读"**（`pager_get` 次数，含缓冲池命中），
  不是磁盘 IO。KNN 只读不写，所以这里逻辑读 ≈ 物理读，
  但**没有**分别测 —— 空间模态还没接 pager 的四口径统计（那是 v1.3 给 FT 做的）。
- **KNN 没有走 SPI / 公开 API**：现在只能通过 `rtree_knn()` 直接调用，
  公开的 `db_geo_knn()` 属于步骤 5。
- **没有删除后的 KNN 语义**：死条目的处理（标记死条目）属于步骤 5/6。
  现在树里没有死条目，所以"删除后 KNN 不返回死点"这条验收（A6）还没法做。
- **单线程**：KNN 没有加 latch，调用方需要自己保证没有并发写。
  公开 API（步骤 5）必须补上 latch。
- **堆是内存里的最小堆，不是磁盘上的外部排序**：点数规模大到堆本身成为瓶颈时，
  需要换成"分块 + 归并"的路子 —— 本轮没做，也没测那个规模。

### 步骤 4 · Z-order 对照实现（A5 的另一半）（2026-11-04）

**结论：完成（A5 达标；**两处与计划的偏差**如实记录在下面）。**

#### 落地的东西

| 文件 | 行数 | 内容 |
|---|---|---|
| `src/modalities/geo/zorder.{h,c}` | 213 + 424 | Morton 编码/解码 + 坐标量化 + 固定网格桶 + 窗口查询（命中集 / 候选集 / IO 口径） |
| `test/unit/test_geo_zorder.c` | 约 330 | 量化 / 编解码往返 / 窗口全等 / **R4 超集断言** / IO 口径 / 边界 |
| `bench/geo_bench.c` | 约 600 | A5：均匀 / 聚簇 / 高斯基组 三组分布下 R-tree 与 Z-order 的窗口 IO 对照 |

#### 两个设计决定

**① 固定网格桶，而不是 BigMin 区间分解。**

计划里写的是"BigMin 区间分解 + 塞进现有 B+tree"。
BigMin 要解的是"一个矩形在 Z 序上拆成**几个连续区间**"，
实现复杂且容易错（错了一点就是**漏点**）。
而**固定网格桶天然是超集**：落在窗口里的格子整桶扫、再按矩形逐点过滤 ⇒
不漏点（R4 的超集断言正好查这一条），代价是多扫一些不在窗口里的点。
代价是 IO 单位从"页"退化成"桶"，所以基准里额外给了
「**等效页数 = 扫过的点数 / 203**」这个**同一把尺子**的口径。

**② 对照实验的坐标必须让两边看到"同一个数"。**

这是本步骤踩到的**最要命的坑**（记为坑 M5-6）：
R-tree 的 MBR 是 **float**（24 位有效数字），Z-order 的坐标是量化的 **u32**（32 位）。
在 [0,1000) 上按 32 位量化时，量化步长 ≈ 2.3e-7，而 float 在 1000 附近的精度 ≈ 6e-5
⇒ **float 分辨不出相邻的量化值**：实测 20 万个点塌成 **16 万 2275** 个不同的 float 位置。
于是 R-tree 的"全扫"只捞回 162275 个点、Z-order 捞回 200000 个 ——
**两边看的根本不是同一批点**，IO 对比整个作废。
防线：把对照实验的坐标限制在 **16 位整数网格**上
（整数 < 2^24 ⇒ float 精确表示 ⇒ 两边的点集逐点相同）。
**教训**：跨精度比较之前，先问"两边的数是不是同一个数"。

#### A5 实测（10 万点，20 个 1% 面积窗口）

| 分布 | R-tree 小窗口 | Z-order 小窗口 | Z-order 等效页数 | 全扫（R-tree / Z-order） |
|---|---|---|---|---|
| 均匀 | **21.45 页** | 18.05 桶 | 8.68 页 | 723 页 / 1024 桶 |
| 聚簇（100 簇心 σ=2） | **11.90 页** | 1.60 桶 | 7.74 页 | 713 页 / 101 桶 |
| 高斯基组（扁带） | **29.65 页** | 2.00 桶 | **54.99 页** | 706 页 / 28 桶 |

**每组一句解释**：

1. **均匀**：Z-order 的固定网格与点怎么铺开无关，1% 窗口只碰到 18 个格子 ⇒ 18 桶；
   R-tree 要一路下探到叶子 ⇒ 21.45 页。按扫过的点折算，Z-order 更省（8.68 页）。
2. **聚簇**：簇很小（σ=2），一个格子装着整个簇，窗口蹭到簇边就整桶扫完；
   但桶本身装得下（341 条），1 个桶就够 ⇒ 1.60 桶 / 7.74 等效页，仍略优于 R-tree。
3. **高斯基组**：点挤在一条扁带里，**固定网格与带的形状对不上** ——
   窗口只碰到 2 个格子，可这 2 个格子里绝大多数点**不在窗口里**（白扫）
   ⇒ 折算 54.99 页，**比 R-tree 还多 1.85 倍**。

**结论**：固定网格**不怕点散，怕形状歪**；
R-tree 的包围盒跟着数据走，三种分布都稳（11.9~29.7 页）。

#### 如实记录（不注水）

- ⚠️ **两处与计划的偏差**：
  ① "BigMin 区间分解"**未做**，改成固定层级网格桶（理由见上面决定 ①）；
  ② "塞进现有 B+tree"**未做**，桶放在内存里，IO 口径是"桶数"而不是"B+tree 页数"
  （两者的换算关系：桶 341 条 vs 叶页 203 条，对 Z-order **有利**，
  所以基准里另给了同一把尺子的"等效页数"）。
- **Z-order 没有页、没有锁、没有 WAL**：它是对照用的**内存结构**，
  不参与 SPI、不接公开 API，崩溃后重建即可 —— 这一点与 R-tree 不同，不要混用。
- **网格层级 `cell_bits` 是要调的旋钮**：太小 ⇒ 格子太多、桶碎；
  太大 ⇒ 一个格子里塞太多点、超集变大。本轮按"每格平均 ≈ 一个桶容量"选，
  均匀分布下 cell_bits=5（1024 格）。
- **`buckets_touched` 是累加语义**（坑 M5-7）：不清零就会拿到累计值，
  症状是"小窗口桶数 > 总桶数"。
- **A5 的判据只对 R-tree 侧是"必须达标"**：Z-order 侧不达标**恰恰是对照要展示的事实**
  （固定网格对分布敏感），基准里把它打成 ⚠ 而不是算失败。
- **没有接 SPI、没有公开 API、没有删除/reindex、没有 WAL** —— 那些属于步骤 5/6。
